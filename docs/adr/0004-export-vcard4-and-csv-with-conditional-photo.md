# ADR 0004: 出力は vCard 4.0 と CSV とし、PHOTO は条件付きで埋め込む

## Status

- Accepted

## Decision Drivers

- 確定した名刺を、連絡先アプリへそのまま取り込みたい
- 表計算や他のツールで一覧・編集したい
- 名刺画像を連絡先の写真として持ちたいが、出力ファイルを無闇に大きくしたくない
- 項目名は vCard 4.0 のプロパティ名を正とし、CSV でも同じ語を使いたい

## Context

vCard には複数のバージョンがあり、4.0 は `PHOTO` に data URI を許す。CSV は列ベースで、写真のようなバイナリを自然に表せない。

名刺画像は 1 枚に複数の名刺が写りうる（ADR 0003）。その場合、画像全体をどの名刺の写真とするかは決められない。一方、1 枚から 1 件だけ得られた場合は、その画像を名刺の写真として扱える。

## Options Considered

- vCard のみ: 連絡先としては十分だが、一覧や編集には向かない
- CSV のみ: 表計算では扱いやすいが、連絡先として取り込めない
- vCard 3.0 を使う: 対応範囲は広いが、`PHOTO` の扱いと項目名の基準が古い
- vCard 4.0 + CSV の両方を出力する

## Decision

- 書き出し形式は vCard 4.0 と CSV の両方とする。利用者はどちらかを選べる
- 項目名は vCard 4.0 のプロパティ名を正とする。CSV の列名も同じ語を使い、日本語の表示名は UI の翻訳にとどめる
- vCard の `PHOTO` は、その名刺の取り込み元の候補が 1 件だけのときに、縮小版を data URI として埋め込む。候補が複数件のときは `PHOTO` を省略する
- 埋め込む画像は表示用の縮小版とし、保持している元画像は置き換えない
- CSV は 1 行 1 名刺とし、画像そのものは含めない。取り込み元の名刺画像を参照する列として `photo_sha256`（無加工で保持した画像の内容ハッシュ）を含める
- CSV で 1 つの項目が複数の値を持つ場合（`TEL`、`EMAIL` など）は、`;` で区切って 1 セルにまとめる。1 行 1 名刺を保ち、値ごとに行は分けない
- `UID` は名刺ごとに安定した値を書き出し、再取り込み時の識別に使えるようにする。vCard と CSV のどちらも `urn:uuid:` 形式の同じ値にする
- CSV のヘッダは `uid,fn,n,org,title,tel,email,adr,url,note,photo_sha256` の順で固定する

## Consequences

- Positive: 連絡先アプリと表計算の両方で利用できる
- Positive: 複数件写る画像から誤った写真を埋め込まない
- Negative: vCard と CSV で持てる情報が非対称になる（CSV は写真そのものを持たず、`photo_sha256` で参照する）
- Negative: 縮小版の生成と、`PHOTO` の有無による分岐のテストが必要になる
- Follow-up: CSV に列を追加する場合は、公開契約として列名と並び順の互換性をこの ADR に追記する

## Adoption and Exceptions

- `PHOTO` を無条件に埋め込む変更を加えない
- 項目名を vCard 4.0 以外の語へ変える場合は、GLOSSARY とこの ADR を同じ変更で更新する
- vCard 3.0 を追加する場合は、`PHOTO` と `UID` の扱いを定めた新しい ADR を用意する
